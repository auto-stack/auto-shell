## NL→AutoLang：`ash ask` 子命令 + eval_auto + Agent 生成-执行循环（§6）

### 范围（ash ask 子命令，已确认）
`ash ask "<自然语言>"` → 云端大模型生成 AutoLang 脚本 → eval_auto 执行 → 失败则 Agent 自我修复（ReAct）→ 输出结果。

### 依据（已核实）
- `Shell::execute_auto`（shell.rs:1517，私有）+ `session_run`（1502）已能跑 AutoLang（含 fn/while/try-catch）——§6.2 只需 pub 包装
- `Agent::run` ReAct 循环已就绪（auto-ai-agent）——§6.3 的"生成-执行-修复"用 ReAct 自然实现
- `Coder` role（tier=Max，代码生成）已有，但需 AutoLang 专用 prompt
- AshCommandShellThread 模式（专用线程持有 Shell）已验证——EvalAutoTool 复用它

### 设计

#### 1. `Shell::eval_auto`（§6.2，shell.rs）
pub 包装私有 `execute_auto`：
```rust
pub fn eval_auto(&mut self, code: &str) -> Result<Option<String>> {
    self.execute_auto(code)
}
```
一行改动（execute_auto 已有 begin_run/end_run 安全包装）。

#### 2. `EvalAutoTool`（新，ash_command_tool.rs 或新文件）
把 eval_auto 包成 Tool，让 Agent 能执行 AutoLang 代码并看到结果/错误。**复用 AshCommandShellThread 模式**（Shell 非 Send，经 channel 执行）：
- 但 eval_auto 执行的是 AutoLang 代码（不是 shell 命令），所以需要一个独立的处理路径
- 最简洁：EvalAutoTool 持有 `mpsc::Sender`，专用线程收到代码后调 `shell.eval_auto(code)` 而非 `execute_for_agent`
- 或者：扩展 AshCommandShellThread 支持"eval_auto 模式"的请求

我倾向**给 AshCommandShellThread 加一个 eval_auto 请求类型**（CmdRequest 已有 cmd+respond，加一个 EvalAuto 变体）。但这增加复杂度。更简单：**新建一个轻量的 EvalAutoShellThread**（复制 AshCommandShellThread 模式，但调 eval_auto）。或：让 AshCommandShellThread 的循环同时处理两种请求（shell cmd / auto eval）。

最干净：扩展 CmdRequest 为 enum（ShellCmd / AutoEval），AshCommandShellThread 循环 match 分发。

#### 3. AutoLangCoder Role（新，或自定义 prompt）
不复用 Coder（它的 soul 是通用项目代码）。用一个自定义 Role（或直接 SmartCommandRole 的变体）：
- system prompt：教 LLM AutoLang 语法 + ash 的 system() 桥 + 上下文
- tier=Max（云端，代码生成需要强模型）
- 注册 EvalAutoTool

实际上用一个自定义 struct impl Role（像 SmartCommandRole 那样，留在 auto-shell）。

#### 4. `ash ask` 子命令（main.rs + 新 cli 模块）
main.rs 加 `"ask"` 分支 → 委托给新函数：
- 构造 Agent（AutoLangCoder role + EvalAutoTool + context）
- `agent.run_stream(nl, on_event)` —— ReAct 循环（LLM 生成脚本 → eval_auto 执行 → 看结果 → 修复）
- 渲染 StreamEvent（Delta 显示生成的脚本、Tool 显示执行结果）

### 测试（TDD）
- **eval_auto**：pub 方法能跑 AutoLang（已有 execute_auto 测试模式）
- **EvalAutoTool**：执行简单 AutoLang（print/算术）返回结果；语法错误返回错误信息
- **CmdRequest enum**（如扩展）：ShellCmd 和 AutoEval 都能正确分发
- 端到端 `ash ask`（需 daemon，soft-skip）

### 不做
- F3 自动升级（保持 ask 独立入口）
- 完整 AutoLang IDE（留 AutoCoder）
- 脚本沉淀为实例（§1 提的长期愿景）

### 验证
- cargo test -p auto-shell --lib（eval_auto + EvalAutoTool 测试）
- 回归全过
- 手动 `ash ask "列出当前目录的所有 .rs 文件并统计行数"`（需 daemon）

### 风险
- CmdRequest 扩展为 enum 会动 AshCommandShellThread（已测的代码）——有回归测试保护
- Agent 生成的 AutoLang 语法可能不标准——LLM 可能需要几轮修复（max_turns 控制）
- eval_auto 执行任意代码——有 DANGER_PATTERNS 保护（system() 调用仍走 AshCommandTool 的危险检查）
