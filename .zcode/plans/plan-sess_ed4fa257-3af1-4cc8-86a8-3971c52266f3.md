# 修复两个 parity 缺陷（case 74/80）

## 根因（已用代码确认）

### 缺陷 B：`> find` 捕获为空（字段名不匹配）
- **位置**：`ash/auto-shell/src/cmd/commands/find.rs:153-155`
- find 构造的结果对象只有 `path` 和 `type` 字段：
  ```rust
  obj.set("path", Value::str(&rel));
  obj.set("type", Value::str(if is_dir { "dir" } else { "file" }));
  ```
- 而 bash_compat 渲染器 `format_file_list_as_bash`（`ash-core/src/cmd/value_helpers.rs:232-236`）硬编码只读 `name` 字段：
  ```rust
  .filter_map(|item| obj_field_str(item, "name"))
  ```
- find 的对象没有 `name` → 全部被 filter_map 丢弃 → `names` 为空 → 返回 `Some(String::new())` → 捕获空串。
- **对比 ls**：`build_file_entry_obj`（`cmd/fs.rs:328`）设置了 `name` 字段，所以 ls 能正常渲染。

### 缺陷 A：system() 桥返回空/乱码（未开 bash_compat）
- **位置**：`ash/auto-shell/src/host.rs:127`（`ShellHostBridge::system`）
- `system()` 调 `shell.execute(cmd)`，但没设置 `bash_compat`。
- `format_output`（shell.rs:891）默认走交互式表格渲染（ratatui）：对结构化命令（find/ls/wc 的 FileList/CountResult）渲染表格或返回空，而非 bash 纯文本。
- case 80 的 `var tree = > find`（在 fn 内，brace_depth>0）被 shell.rs:2448 改写成 `system("find ...")`，所以 case 80 也走 system 桥，受缺陷 A+B 双重影响。
- **为何 cat/echo 正常**：它们返回 `AtomType::Text`（非 structured），`format_output` 走 `into_text()` 直接返回。

## 修复方案（用户已选定：execute_capture 路径）

### 修复 B：find.rs 补 `name` 字段（必需，否则即便开 bash_compat 仍空）
`find.rs:151-157`，参照 ls 的 `build_file_entry_obj`，给每个对象补 `name`（用 file_name）：
```rust
if type_match && name_match {
    let rel = pathdiff(&root, &path);
    let mut obj = Obj::new();
    obj.set("path", Value::str(&rel));
    obj.set("name", Value::str(&file_name));   // 新增：与 ls 一致
    obj.set("type", Value::str(if is_dir { "dir" } else { "file" }));
    results.push(Value::Obj(obj));
}
```
`file_name` 已在 find.rs:128 计算（`entry.file_name()`），直接复用。这样 `format_file_list_as_bash` 能读到 name，find 输出 `./a.log` 每行一个（与 bash `find` 一致）。

### 修复 A：新增 `Shell::execute_capture` 方法 + system 桥改调它
**设计要点**：`execute_capture` = "以 bash 兼容纯文本模式执行并捕获 stdout"。它本质是 `execute_for_agent(cmd, false, true)` 的语义（json_mode=false, bash_compat=true），但语义命名更清晰——专用于"程序化捕获"场景（system 桥），与"交互展示"（execute）分离。

**1. shell.rs 新增方法**（紧邻 `execute_for_agent`，shell.rs:965 之后）：
```rust
/// Execute a command in bash-compatible capture mode and return its stdout.
///
/// Used by the `system()` host bridge (AutoLang `system("cmd")`) so that
/// structured commands (find/ls/wc/grep) render as bash-style plain text
/// instead of interactive ratatui tables. This separates "programmatic
/// capture" (machine-readable stdout) from "interactive display" (`execute`).
/// Mirrors `execute_for_agent`'s bash_compat toggling.
pub fn execute_capture(&mut self, input: &str) -> Result<Option<String>> {
    let was_compat = self.bash_compat;
    self.bash_compat = true;
    let result = self.execute(input);
    self.bash_compat = was_compat; // restore prior state
    result
}
```
注意：用 `was_compat` 保存恢复（而非硬置 false），避免在已开 bash_compat 的上下文（如 `--bash-compat` 脚本）里破坏状态。这是比 `execute_for_agent` 更稳健的写法。

**2. host.rs 的 system 桥改调 execute_capture**（host.rs:127）：
```rust
fn system(&self, cmd: &str) -> String {
    let s = self.state.lock().unwrap();
    unsafe {
        match s.shell() {
            Some(shell) => {
                match shell.execute_capture(cmd) {   // 原 shell.execute(cmd)
                    Ok(Some(out)) => out.trim_end_matches('\n').to_string(),
                    Ok(None) => String::new(),
                    Err(_) => String::new(),
                }
            }
            None => String::new(),
        }
    }
}
```

## 不做的事（YAGNI）
- 不修 `> ls -R`（"program not found"）——这是 ls 命令 flag 支持的独立次要缺陷，case 80 改用 `> find` 后已绕开，不在本次范围。
- 不修外部命令（date/gzip）的 capture_output=false 问题——case 74/80 用的是注册命令 find，不涉及外部命令捕获。这是更大的独立任务。
- 不改造 format_file_list_as_bash 回退 path 字段——直接给 find 补 name 更贴合 ls 既有约定，一处改动。
