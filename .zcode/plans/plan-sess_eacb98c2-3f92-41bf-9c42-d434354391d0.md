# Plan 032:ASH 智能补全系统实施计划

> 基于 `designs/032-intelligent-completion.md`,结合代码库现状勘探(029 §2.3 基础设施已落地、suggest.rs 后台线程模式可复用、reedline Completer 同步约束)。
> **范围**:完整 M0-M3,按里程碑 TDD 逐个交付。预估 ~1500 行 / 4-5 周,本计划拆成 4 个独立可验证的 PR。

---

## 关键工程决策(勘探得出,非臆断)

1. **AI 异步刷新策略 = 滞后一次按键**(复用 suggest.rs 的 `static Mutex<Option<...>>` + `std::thread::spawn` + `take()` 模式)。reedline `Completer::complete` 纯同步无 async 入口;本次 `complete()` 先返回静态结果并 fire 后台 AI 线程,**下一次按键**的 `complete()` 读缓存返回 AI 结果。零额外依赖,最低风险。

2. **029 基础设施已落地,直接复用**:`Shell` 访问器(`last_exit_code/last_command_line/last_command_args/aliases/dir_stack`,shell.rs:416-440)、`build_context_block(&shell)`(ai_context.rs)、`auto_ai_client::AiClient`(同 ask_ai/suggest.rs 用法)全部就位。**不重复定义访问器**。

3. **NL 补全复用 ask_ai 的 prompt + context 模式**(不重写翻译逻辑),差异仅在触发时机与返回包装。

4. **`AiClient::new()` 会阻塞式 lazy-start daemon**,必须在后台线程内创建(像 suggest.rs:60 那样),绝不放在 `complete()` 热路径。

```rust
        // 结果(过滤 prefix 后)写入 AI_PENDING(key=line)

}
pub fn take_ai_pending() -> Option<Vec<Completion>> { /* .take() */ }
```
- **CtxSnapshot**:为了跨线程,把 `CompletionContext` 的可发送字段(`current_dir: PathBuf`、`last_command: Option<String>`、`history: Vec<String>`、`aliases: HashMap`)clone 进闭包(`Shell` 本身非 Send)。
- **500ms 超时**:`tokio::time::timeout(Duration::from_millis(500), client.complete(&req))`,超时或错误 → 不写缓存(降级,像 suggest.rs 那样尽力而为)。
- **触发条件**(在 complete() 里):仅当 `provider.resolve()` 返回候选 < 3 且当前是子命令位时才 fire(省本地算力)。
- **消费**:下一次 `complete()` 开头 `take_ai_pending()`,若 key 匹配当前 line 则把 AI 候选(标记 `CompletionKind::AiSuggested`)并入并交给 `context_rank`。
- **测试**:mock `trigger_ai_subcommand`(注入假 client / 直接测 take/写缓存逻辑)→ 缓存读写正确、超时降级不 panic、触发阈值正确(<3 才 fire)。

### M2.3 集成进 `ShellCompleter::complete`
**文件**:completions_reedline.rs:201
```
complete(line,pos):
  1. take_ai_pending() → 若 key 匹配,并入候选集(标记 AiSuggested)
  2. provider.resolve(静态+动态) → 候选 A
  3. 若 len(A)<3 且子命令位 → fire trigger_ai_subcommand(后台,本次不阻塞)
  4. 若首 token 未知命令 → fire trigger_nl_to_pipeline(后台)
  5. context_rank(A + AI候选)
  6. 转 Suggestion 返回
```
- AI 候选在 Suggestion 的 `extra` 里带 `"ai"` tag(completions_reedline.rs:184 `kind_tag` 已支持 `AiSuggested => "ai"`,**无需改 kind_tag**)。
- **降级保证**:Ollama 未装/daemon 起不来 → `AiClient::new()` 失败 → 后台线程静默不写缓存 → 行为完全等同 Plan 021(纯静态+动态)。**测试**:无 daemon 时 complete() 不 panic、返回静态结果。

## M3:缺失动态源(~200 行,0.5 周)

### M3.1 ssh hosts 补全
**文件**:`ash/auto-shell/src/completions/definitions/ssh.rs`
- `ssh_spec()`/`scp_spec()` 的 destination arg 加 `.source(...)`。
- 用 `CompletionSource::command`(spec.rs:284 现有 API)读 ssh hosts:
  - Linux/macOS:`grep -iE '^Host |^HostName ' ~/.ssh/config ~/.ssh/known_hosts 2>/dev/null | awk '{print $2}'`(纯 shell-out,无需扩展枚举)。
  - Windows:`type %USERPROFILE%\.ssh\config` 经 `cmd /C` —— **但跨平台 shell-out 已由 `ShellCompleter::execute_command`(completions_reedline.rs:161)处理**(它按 `cfg!(windows)` 选 cmd/sh),所以 spec 里写的命令需平台中立或用占位。
- **平台差异处理**:在 ssh.rs 里 `cfg!` 分支返回不同 cmd 字符串(Linux 用 awk,Windows 用 findstr/PowerShell),或新增一个纯 Rust 解析函数读 `~/.ssh/config`(更稳,推荐)。
- **测试**:用临时 `~/.ssh/config` fixture,断言 host 列表正确解析;`register_all` 后 `provider.has_spec("ssh")` 为真。
