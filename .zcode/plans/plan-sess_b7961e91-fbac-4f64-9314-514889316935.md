## 目标与范围

把 ash pipeline 从「每段 eager 全量 materialize」升级为「算子是 `Iterator`、逐行 pull、filter/take/select 流式、sort/aggregate 末端断流 collect」。外加修一个静默丢数据 bug + 统一 10 个格式转换器。

**范围外**（明确不做）：Polars、批处理、投影下推、算子融合、完整查询计划优化器、删除现有 10 个格式命令、lazy 的 explain。

**测试约定**：ash-core 用内联 `#[cfg(test)] mod tests`（无 tests/ 目录）；auto-shell 用 `tests/` 集成测试。**TDD：先写失败测试再实现**。

## M0：Stream bug 修复 + Format trait 统一（1-2 周，~600 行）

### M0.0 — 建立回归基线（前置，无代码改动）
跑全量测试记录基线（约 1107 个 test fn），确认 `legacy_json_compat.rs` 5 个全绿。

### M0.1 — 修复 Stream bug（TDD）
- **先写失败测试** `tests/stream_bug_fix.rs`：用**真外部命令**（非 `find`）构造产 `ExternalStream` 的管道 → DSL 段，断言不丢行（当前得空数组 → 失败）。
- **实现**：`shell.rs:1128` 把 `_` 分支拆成显式 match —— `Stream → collect items`、`ExternalStream → read_all → 按行成 Array`、`Empty/None → 空数组`。
- **守护**：`pipeline_to_json`（`shell.rs:973`）+ `legacy_json_compat.rs` 回归。

### M0.2 — `Format` trait + 5 实现 + 注册表（放 `ash-core/src/format.rs`）
- trait：`fn name/parse(&str)->Result<Value>/serialize(&Value)->String` + `FormatError`。
- 5 实现：`JsonFormat/CsvFormat/YamlFormat/XmlFormat/TomlFormat`，复用现有 free function。
- `FormatRegistry: HashMap<String, Arc<dyn Format>>`。
- **设计留白决策**：现有 `to_*` 有不统一 config（indent/root_name/path/delimiter）。`Format::serialize` 用**各格式默认 config**，命令层通过参数另行传入（用户接口不变）。

### M0.3 — 10 个格式命令内部改用 Format（用户接口不变）
逐个改造 9 个走有损桥 `atom_to_pipeline_data`（`pipeline_convert.rs:35`，`unwrap_or_default()` 静默吞错）的命令，委托给 Format，把静默吞错改成显式错误传播。**v1 不删现有命令**。

**M0 验收**：bug 测试绿 + 028/007 回归绿 + Format 单测绿 + 10 命令行为不变。

## M1：LazyNode + impl Iterator（2 周，~800 行，放 `ash-core/src/pipeline/lazy.rs`）

### M1.0 — 提升 `get_field` 为 pub（前置，单独提交先跑回归）

### M1.1 — `LazyNode` enum + `impl Iterator`
- **先写流式性测试**：filter 在 Source 未读完时已产出（lazy vs eager 的本质区别）。
- `LazyNode` 7 变体（设计 §3.1）：`Source(Vec<Value>)` / `StreamSource(Box<dyn Iterator + Send>)` / `Filter` / `Take` / `Select`（流式） / `SortBy` / `Aggregate`（断流点）。
- 新建 `AggOp`（7 变体）。
- `impl Iterator`，断流点用内部 `SortState{Pending, Sorted}`，首次 `next()` 触发 collect。

### M1.2 — `build_lazy` + `collect`
- `build_lazy(ops: &[PipelineOp], source: Value) -> LazyNode`（保留 `apply` eager 不动）。
- `LazyNode::collect() -> Value`。
- **测试**：lazy 与 eager 结果等价（覆盖**全部 16** 个 PipelineOp）。

**M1 验收**：流式性绿 + 16 算子 lazy/eager 等价绿 + 现有 1107 回归全绿。

## M2：谓词下推 + shell.rs 累积改造（1-2 周，~500 行，lazy 真正产生价值）

### M2.1 — 谓词下推 pass（v1 只两条保守规则，不跨 sort/agg）
规则 1：filter/select 顺序交换（字段在 select 前存在才换）；规则 2：相邻 filter 合并成 and。

### M2.2 — shell.rs 累积连续 DSL 段 → build_lazy（v2 策略）
当前每段 DSL 单独 `apply`（`shell.rs:1130`）；改为循环里维护 `pending_ops: Vec<PipelineOp>`，遇非 DSL 段或 is_last 时 flush 成 `build_lazy(&all_ops, source).collect()`。
- **守护**：`pipeline_dsl.rs`（6 个 Plan 024）+ `legacy_json_compat.rs`（5 个）。

### M2.3 — 性能验证
1 万行 source 对比 eager vs lazy 峰值内存（设计目标 < eager 50%，主要在 take/early-exit 场景占优）。

**M2 验收**：下推两规则 + 不跨断流点 + 多段 DSL 端到端正确 + 性能数据记录 + 全量回归绿。
